# Django-NB Project Context

## Project Overview
A Django application with Nginx reverse proxy support, multi-language interface, and AI chat capabilities.

## Key Technologies
- **Framework**: Django 6.0.8
- **Database**: SQLite (db.sqlite3)
- **Server**: Nginx reverse proxy
- **AI Integration**: Ollama (LLM model configured via OLLAMA_MODEL env var)
- **API**: Django REST Framework

## Internationalization
- **Languages**: English (en) and German (de)
- **Locale Path**: `locale/`
- **Cookie Domain**: Dynamically set from ALLOWED_HOSTS to support both `domain.com` and `www.domain.com`
- **Cookie Age**: 1 year

## Deployment
- **Production Hosts**: Read from `.env` ALLOWED_HOSTS (comma-separated, supports both `domain.com` and `www.domain.com`)
- **Development Hosts**: localhost, 127.0.0.1, [::1] (when DEBUG=true)
- **Media Root**: BASE_DIR (with security TODO: move to dedicated media/ directory)
- **Static Files**: `/static/` URL, collected to `staticfiles/` directory
- **News Static Files**: Located in `news/` directory

## Core Features
1. **AI Lab (`ai_lab`)**: Ollama-powered AI chat integration (renamed from the earlier `chat` page/view/URL — no `chat` naming should remain in code, templates, or routes). Requires the user to be logged in (`@login_required`).
2. **User Contact Methods**:
   - Schedule a meeting/appointment
   - Send messages
3. **Admin Panel**: Django admin interface
4. **REST API**: Django REST Framework support
   - `NewsViewSet` allows public (`AllowAny`) read access (`GET`/`HEAD`/`OPTIONS`) but requires an authenticated user (`IsAuthenticated`) for write operations (`POST`/`PUT`/`PATCH`/`DELETE`).
5. **Authentication**: Django built-in login/logout system
   - Login and logout are available through the profile dropdown in the navbar.
   - Registration uses a custom `EmailUserCreationForm` (email doubles as the username) and requires email verification before the account can log in — see "Branch-Specific Changes" below.
   - Keep the Register dropdown item linked to the named `register` route.
6. **Navigation**: Localized navbar with language and profile dropdowns

## Branch-Specific Changes

- **AI Lab access**: `ai_lab` view/URL/template require `@login_required`. Do not remove that restriction without an explicit request.
- `LOGIN_URL`, `LOGIN_REDIRECT_URL`, and `LOGOUT_REDIRECT_URL` point to the built-in auth routes and redirect to `home` after authentication actions.
- Cookie domains are disabled in debug mode and for local IP/localhost hosts so local development works without a production domain.
- **News API permissions**: `NewsViewSet.get_permissions()` returns `AllowAny` for safe methods and `IsAuthenticated` for write methods. Keep this split; don't revert to a single `permission_classes = [AllowAny]`.
- **Registration + email verification flow** (see [webapp/views.py](webapp/views.py), [webapp/forms.py](webapp/forms.py), [webapp/tokens.py](webapp/tokens.py), [webapp/urls.py](webapp/urls.py)):
  - `EmailUserCreationForm.save()` creates the user with `is_active=False`. New accounts are **inactive by default** and cannot log in until verified.
  - `register` view saves the user, generates a signed verification link via `email_verification_token` (a `PasswordResetTokenGenerator` subclass in `webapp/tokens.py` that also hashes in `is_active`, so the token is invalidated once used), stores the user's email in `request.session["pending_verification_email"]`, and redirects to `registration_pending`.
  - `registration_pending` view pops the email out of the session (one-time read) and renders `website/registration_pending.html`, which tells the user to check their inbox/spam and shows the email the link was sent to, plus a `support_email` (`info@devmyai.com`, from `settings.SUPPORT_EMAIL`) contact.
  - `verify_email` view (URL: `verify-email/<uidb64>/<token>/`) validates the token, sets `is_active=True`, logs the user in, and redirects to `home`. An invalid/expired/already-used token renders `website/verify_email_invalid.html` with a 400 status.
  - **No real email server is wired up on this branch.** `_send_verification_email()` only logs the verification link via `logger.info(...)` (goes to `logs/app.log` and console) — it does not call `send_mail`. There is a `TODO` in `views.py` noting that a real email backend/server should be added on a separate branch. Do not reintroduce `EMAIL_BACKEND`/`EMAIL_HOST`/`DEFAULT_FROM_EMAIL` settings or `send_mail`/`render_to_string` calls unless the user explicitly asks for that.
  - `settings.SUPPORT_EMAIL` (default `info@devmyai.com`) is the only email-related setting kept in `config/settings.py`.

## Playwright Page Objects

- Browser tests live in `tests/playwright/test_*.py`; reusable page objects live in `tests/playwright/pages/` and inherit from `BasePage` when appropriate.
- Keep selectors and page interactions in the owning page object. Tests should use page-object methods rather than calling `page.locator()` or performing page interactions directly.
- Keep assertions about expected behavior in the test. Page objects should expose focused actions and observations, such as `load()`, `is_heading_visible()`, and `get_title()`.
- Reuse `BasePage` for shared browser operations. Follow existing page-object URL patterns, including `BASE_URL` where the page already uses it.
- `pytest.ini` configures the `smoke`, `regression`, `server`, and `test` markers. Use pytest to run browser tests, for example `pytest -m smoke -n auto` or `pytest tests/playwright/test_home.py`.

## Important Settings
- **SECRET_KEY**: Required, must be set in `.env` (raises ImproperlyConfigured if missing)
- **DEBUG**: Controlled by env var, defaults to False
- **SUPPORT_EMAIL**: Contact address shown to users (e.g. on the pending/invalid email-verification pages); defaults to `info@devmyai.com`
- **CORS/Security**: NoIndexMiddleware applied for SEO control
- **Logging**: Rotating file handler to `logs/app.log` (5MB per file, 5 backups)

## File Structure
- `config/settings.py` - Main settings
- `config/urls.py` - URL routing
- `webapp/` - Main app with models, views, middleware, context processors
- `locale/` - Translation files
- `logs/` - Application logs
- `staticfiles/` - Collected static files
- `db.sqlite3` - SQLite database

## Environment Variables Required
- `SECRET_KEY` - Django secret key (mandatory)
- `ALLOWED_HOSTS` - Comma-separated list (e.g., "domain.com,www.domain.com")
- `DEBUG` - Boolean (0/1, true/false, yes/no, on/off)
- `OLLAMA_MODEL` - LLM model name (default: "llama3.2:1b")
